# System map

## End-to-end flow

```text
Developer/agent
  -> local repository: pulse-web
  -> GitHub: zikosichi/pulse-fitness
  -> push/merge to main
  -> Vercel detects the commit
  -> npm install/build using the Next.js preset on Node.js 24.x
  -> Vercel Production deployment
  -> www.pulsefitness.ge

Visitor DNS lookup
  -> .ge registry
  -> ns1.ge.domains / ns2.ge.domains
  -> www CNAME to Vercel
  -> Vercel CDN/application

Incoming email
  -> info@pulsefitness.ge
  -> ge.domains MX records
  -> mx1.improvmx.com / mx2.improvmx.com
  -> ImprovMX alias
  -> tevzadzedavit@gmail.com
```

There is no application database, authentication system, CMS, API service, Supabase project, Cloudflare Worker, or server-managed mailbox in the active application.

## Workspace map

The shared Space root is not itself a Git repository. The active Git repository is the `pulse-web/` child directory.

| Path | Status | Purpose |
|---|---|---|
| `pulse-web/` | **Active** | Next.js production application and Git repository |
| `Website Code/` | Legacy; do not use | Older Lovable/Vite/React implementation |
| `Site/` | Legacy; do not use | Older static HTML/CSS/JS implementation |
| `Assets/` | Reference material | Original and working imagery outside the deployed repository |
| `Brand & Identity/` | Reference material | Brand direction |
| `Wireframes & Mockups/` | Reference material | Layout/content structure |
| `docs/operations/` | **Operational source of truth** | This handbook |

The active repository README explicitly supersedes `Website Code/` and `Site/`. Their package files, Supabase folders, and deployment instructions do not apply to production.

## Application architecture

- Next.js `16.3.1`
- React and React DOM `19.2.8`
- TypeScript
- App Router
- Plain CSS rather than Tailwind
- npm with committed `package-lock.json`
- Self-hosted fonts and static assets under `public/`
- Georgian is the default language; English is selected with `?lang=en` and remembered in browser storage
- No API routes and no external database in the active repository
- Vercel performs the production Next.js build and serves the site/CDN assets

## Runtime configuration

The only application-read environment variable is:

| Variable | Required | Behavior |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | No | Overrides the canonical public origin. Defaults to `https://pulsefitness.ge`. |

Vercel currently has **no project environment variables configured**. The production build therefore uses the fallback in `lib/seo.ts`.

`.env*` and `.vercel` are ignored by Git. If secrets are introduced later, keep them in Vercel Environment Variables and local ignored `.env.local`; never commit them.

## Static assets

Everything under `public/` is shipped to Vercel's public CDN, even if code does not reference it. The repository README records several unreferenced legacy images that remain in `public/` because some have no other source. Do not treat `public/` as private storage.
